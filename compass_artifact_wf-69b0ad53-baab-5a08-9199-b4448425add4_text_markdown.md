# Beautiful, ServiceNow-Native Dashboards + AI Insights: Technical & Competitive Dossier
*Confidence labels: Verified-Documentation / Verified-Practitioner / Verified-HandsOn(ours) / Inference / Unverified. Current as of mid-2026 (July 31, 2026).*

## TL;DR
- **Technically buildable at high quality: YES.** A ServiceNow-native dashboard can reach an estimated ~80–90% of Power BI/Tableau *dashboard* visual richness by embedding libraries like ECharts/D3/Highcharts inside custom Next Experience components or Service Portal widgets — VividCharts is the live existence proof. The structural ceiling is not chart rendering; it is cross-source data modeling, ACL-safe aggregation, and end-user ad-hoc exploration. *(Verified-Practitioner / Verified-Documentation; the % is Inference)*
- **Meaningfully differentiated from existing ServiceNow dashboard tools: PARTIALLY — genuine white space exists.** No shipped ServiceNow-native product combines (a) beautiful custom visualization + (b) AI-driven metric/insight selection + (c) provable ACL-correctness. VividCharts nails (a), does neither (b) nor (c) natively; Now Assist does a narrow (b) but not (a) or (c). *(Inference, based on currently documented capabilities)*
- **Differentiated from Now Assist's native AI: YES today, but the window is closing.** Now Assist's AI viz generation still emits only 5 chart types (single score, line, vertical bar, pie, list) — unchanged Zurich→Australia — and does template selection, not data-shape-adaptive chart-grammar generation. But ServiceNow is aggressively pushing AI analytics systemwide (Otto, Now Assist bundled into all tiers as of April 9 2026, Pyramid-fueled Autonomous Data Analytics), so a pure "AI picks a chart" pitch is already commoditized; the durable moat is bespoke visual quality + provable correctness + adaptive chart-spec generation. *(Verified-Documentation / Inference)*

## Key Findings
1. **Embedding rich JS charting libraries natively is a solved, documented pattern** in both Service Portal widgets and custom Next Experience (UXF/"Seismic") components. Practitioners have shipped Highcharts, Chart.js, and D3 in Service Portal for years; custom components add npm dependency management — a major advantage over Service Portal's manual JS Include model.
2. **VividCharts proves "beautiful + native + Store-distributed + revenue-generating" is real.** Built entirely on the Now Platform, uses D3.js, ships Service Portal chart widgets plus custom components ("Vivid Styled Table"), separates data collection (server-side GlideRecord/GlideAggregate scripts) from visualization, and exports true-to-form PPT/PDF. G2: **4.7/5, 16 reviews (5-star 93%, 4-star 6%)**. It does NOT do AI metric selection or prove ACL-correctness.
3. **The ACL-on-aggregates gap is real and is the single most important correctness issue.** GlideAggregate does NOT enforce ACLs; there is no "GlideAggregateSecure." A documented community case shows an aggregate count of 4 where the user can only drill into 2 records. Custom-component builders must handle this manually — a place a rigorous product can differentiate.
4. **Now Assist's AI analytics is narrow but being pushed hard.** Data Visualization Generation supports only single score, line, vertical bar, pie, list — unchanged from Zurich to Australia. AI Data Explorer (natural-language exploration + AI insights) is the real 2026 thrust, delivered via Otto and bundled Now Assist. No documented capability does data-shape-adaptive chart generation, autonomous KPI discovery, ACL-correctness proofs, or drift-detection.
5. **No BI vendor — ServiceNow or general market — has shipped true generative/adaptive chart-grammar generation matched to the statistical shape of the data.** Tableau Pulse, Power BI Copilot, ThoughtSpot Spotter, Sigma all do template/encoding selection from a fixed chart library, often backed by a semantic layer and deterministic statistical engines. "AI writes a bespoke chart spec fitted to cardinality/distribution" exists in academic research (Data2Vis, Draco, VizML, Microsoft Flint) but not as a shipped enterprise feature. This is the closest thing to real white space in the thesis.

## Details

### PART A — How to actually build beautiful, native ServiceNow dashboards

**A1. Concrete embedding patterns (Verified-Practitioner / Verified-Documentation)**

*Service Portal widgets (AngularJS-based, older but fully supported):*
- Canonical pattern: create a **JS Include** record pointing to a UI Script containing the library (or a remote URL), attach it to a **Widget Dependency**, then initialize the chart in the widget Client Script or Link function. Server Script runs GlideRecord/GlideAggregate and passes results via the `data` object (Service Portal handles JSON server→client transport). Documented end-to-end for Highcharts (CodeCreative's 4-part series; snhackery's generic chart-widget-plus-config-generator pattern). *(Verified-Practitioner: codecreative.io, snhackery.com)*
- **What breaks:** ServiceNow's own bundled Highcharts (v4.1.9 "Istanbul", loaded via GlideV2ChartingIncludes) collides with Service Portal's jQuery/Angular context. Practitioners report you must download a clean Highcharts build into a UI Script to avoid the conflict, and DOM-selection timing forces a choice between static IDs (init in Client Script) vs. `ng-attr-id`/dynamic (init in Link function). Community verdict: "works but there are some issues." *(Verified-Practitioner)*
- **Bundle/perf:** Service Portal has no package manager, so every dependency is a hand-maintained JS Include; large libraries bloat portal theme load and can't be tree-shaken.

*Custom Next Experience components (UXF/Seismic, built via ServiceNow CLI `snc ui-component`):*
- ServiceNow explicitly documents that if a use case isn't in the 175+ OOB component library, "you can develop custom components using the Next Experience UI Framework and ServiceNow CLI." These are Shadow-DOM-scoped web components deployable as scoped apps/update sets. *(Verified-Documentation: developer.servicenow.com, servicenow.com/docs)*
- **Key advantage over Service Portal:** npm dependency management works, so you can `npm install echarts` into the component build — a practitioner with ~40 custom components over ~3 years cites this as the big benefit. *(Verified-Practitioner: servicenow.com/community, "From Portal Widgets to Next Experience Components")*
- **What breaks:** The deployment toolchain uses an older Webpack that struggles with modern package.json "sub-exports"; a practitioner documents React 18/react-dom/client failing for this reason, and shipped a UIF-as-wrapper-React-inside template (github.com/janmoser87/ui-framework-react-wrapper) as the workaround. Arbitrary modern frameworks are NOT drop-in; plain-JS charting libraries (ECharts, D3, Chart.js) are far safer than React-ecosystem chart wrappers (Recharts, Nivo, Visx). *(Verified-Practitioner: myuibcorner.com, Dec 2025)*

*Licensing (Verified-Documentation):*
- **Highcharts is NOT free for commercial/embedded use.** It's free only under CC BY-NC for personal/non-profit/school. Commercial licenses are per-developer seat — **ComponentSource lists Highcharts Core commercial licenses "from $416.50" per developer (v13.x, updated Jun 11 2026), and checkthat.ai notes paid commercial licenses "starting at $176 per developer annually."** An **OEM license (perpetual only) is required when embedding Highcharts in a product distributed to and hosted by your customers** — directly relevant to any ServiceNow Store app — and OEM is quote-only ("Contact us for a quote," shop.highcharts.com). *(Verified-Documentation)*
- **ECharts (Apache-2.0), Chart.js (MIT), D3 (ISC/BSD), Plotly.js (MIT), AntV (Apache/MIT), Recharts/Nivo (MIT)** are permissively licensed and safe to embed/redistribute in a Store app. **Recommendation: default to ECharts** (richest OOB chart set + permissive license + plain-JS friendly) unless a specific Highcharts feature justifies the license cost.

**A2. Design/asset pipeline using external tools during build (Verified-Documentation / Inference)**
- The delivered artifact stays native because it compiles to a UXF component or Service Portal widget; nothing in the build pipeline touches the runtime. So Figma → Figma-to-code, external LLM code generation, and design-system tooling are all legitimate build-time inputs. The **ServiceNow CLI + `snc ui-component` (uib-component-cli extension)** is the supported deploy path; the **Now Experience UI Framework / Horizon Design System (horizon.servicenow.com)** provides token/style references to match native look. *(Verified-Documentation)*
- **Zurich added an in-UI Component Builder** (create reusable components in UI Builder without leaving the environment / without coding), lowering the barrier. A community "punk" method even shows exporting a component as an XML update set on Yokohama. *(Verified-Practitioner: myuibcorner.com)*
- **Gap:** There is no official Figma-to-ServiceNow-component generator; the last mile (design spec → UXF component code) is hand-coded or LLM-assisted. This is itself a tooling opportunity.

**A3. VividCharts deep dive (Verified-Documentation / Inference)**
- **Mechanism:** BOTH Service Portal chart widgets AND custom components. Architecture separates a "Chart Type" record (server-side script collecting data into a `chartData` array via GlideRecord/GlideAggregate, using `chart.group_by` etc.) from the reusable chart widget that renders it — so the same Donut widget is reused with different data collections. Uses **D3.js**. *(Verified-Documentation: docs.vividcharts.com)*
- **"Vivid Styled Table":** a custom component (a release note fixed a bug where it "did not refresh data as expected when using the UI refresh option") — confirming it is a UXF custom component consuming a data resource. **"Slate":** a free-form canvas ("blank slate") where you place charts/text/shapes with Slate Styles/palettes; the basis of the slide-deck/report editor. *(Verified-Documentation)*
- **Data binding:** queries ServiceNow tables directly via GlideRecord/GlideAggregate in server scripts. **ACL behavior is therefore whatever the developer wrote** — VividCharts does not advertise or document provable ACL-correctness on aggregates; given GlideAggregate's documented ACL bypass, aggregate outputs are ACL-safe only if the chart-type script explicitly re-implements the filter. *(Inference from documented architecture; Unverified whether VividCharts uses GlideRecordSecure/manual filtering.)*
- **Export/signage:** in-platform dashboards and slide decks export to **PowerPoint or PDF in "true-to-form" format**; marketed for wall-monitor/digital-signage display. Sister app **VividSheets** (free on Store) handles KPI/ad-hoc calc and feeds charts. *(Verified-Documentation: help.vividcharts.com, vividcharts.com)*
- **Reviews (Verified-Documentation: g2.com):** **4.7/5 across 16 reviews (5-star 93%, 4-star 6%, no 3/2/1-star).** Praise: PPT-quality reporting in-platform, ease of use, "beautiful visualizations," real-time exec dashboards. Criticism: "The HTML text format on the slates are a big learning curve"; **load times can be slow with larger datasets**; buy-in depends on clean underlying data. **Pricing: not publicly listed** (G2 "No pricing available"; sold via ServiceNow Store / contact seller).
- **Positioning:** cites "97% of ServiceNow's customers are extracting data out of the platform for reporting purposes" (vendor stat — Unverified); wedge is "report where the data lives." Won 2019 CreatorCon Challenge; Elite Technology Partner. *(Verified-Documentation)*

**A4. Other native-viz solutions (Verified-Documentation / Verified-Practitioner)**
- **ServiceNow Dev Program GitHub** (ServiceNowDevProgram; ServiceNow/Creator-Innovation-Gallery; UIB-Examples): open-source custom-component and UI Builder examples — a strong signal the pattern is officially encouraged, but these are demos (menu builders, UI examples), not chart libraries.
- **CodeCreative, snhackery** blogs: reusable generic Highcharts widget patterns — practitioner-grade, not products.
- **Community React wrapper** (janmoser87): proves React-in-UXF is possible but fragile.
- **Perspectium / DataSync and BI-integration ISVs:** the OPPOSITE of the thesis — they EXPORT ServiceNow data to Power BI/Tableau/Snowflake. They exist because native reporting is seen as limited, validating market need, but are disqualified by the "no external BI" constraint.
- **OOB Store dashboards (CIO/CEO/CISO/HR Success):** built on Platform Analytics, drillable, but constrained to the fixed OOB chart palette — not custom-component visual richness.
- **Net:** VividCharts is essentially the only prominent Store-distributed player doing beautiful *custom-component* native visualization; the field is thin.

**A5. ACL-safe data binding (Verified-Documentation / Verified-Practitioner)**
- **Core fact:** `GlideAggregate` and `GlideRecord` do NOT enforce ACLs; `GlideRecordSecure` does (row/field ACL checks), but there is **no GlideAggregateSecure**. `GlideQuery` also does not enforce ACLs by default. ServiceNow's own dev blog: "if you need to enforce ACLs when querying data… use GlideRecordSecure… if you must execute without respect of ACLs, use GlideRecord." *(Verified-Documentation: developer.servicenow.com)*
- **The aggregate trap:** documented community case — GlideAggregate returns count=4, user drills in and sees 2 (2 filtered by ACL). There is no OOB GlideAggregate Query Data Resource in UI Builder; ServiceNow guidance is to use a Transform Data Resource with an ACL, or replicate ACL logic in the aggregate filter. *(Verified-Practitioner)*
- **Best-practice patterns for a rigorous product:** (i) for record-level lists, use GlideRecordSecure; (ii) for aggregates, either iterate GlideRecordSecure and count in-memory (correct but slow at scale), or explicitly inject the persona's effective query/domain filter into the GlideAggregate encoded query and *prove* equivalence to the ACL set; (iii) avoid GlideRecord/GlideAggregate inside ACL scripts (ServiceNow best practice, performance); (iv) note the DB-view/aggregate `glide.db.max_view_records` default of 10,000 as a completeness limit. **A "provable ACL-correctness" layer for aggregates is a real, defensible differentiator because the platform gives you nothing here.** *(Inference, based on currently documented capabilities)*

**A6. Realistic ceiling vs Power BI/Tableau (Inference, based on currently documented capabilities)**
- **Where native CAN match BI (just code it):** chart rendering quality and breadth (any ECharts/D3 type — sankey, chord, network, candlestick, radial, bespoke), animation, in-chart tooltips, theming/brand, PPT/PDF export, wall-signage, responsive layout. VividCharts + G2 praise show "beautiful" is achievable.
- **Where native falls SHORT structurally (not fixable by more code):**
  1. **Cross-source data modeling.** Power BI/Tableau's model layer (relationships, DAX/LOD, blended sources) has no native equal; ServiceNow aggregates live per-table, and cross-table needs Database Views (10k-row + join constraints) or the new RaptorDB/Pyramid path. Combining ServiceNow + external sources natively is weak by design.
  2. **Ad-hoc self-service exploration by end users.** BI tools let a consumer re-pivot/drill arbitrarily; a custom component only exposes the interactions you hard-wired. Native cross-filtering/drill-down is "manually wired and often reported broken."
  3. **ACL-correct aggregation** is a platform gap, not a code gap (above).
  4. **Performance at scale** — browser-side rendering of large series inside a Shadow-DOM component, plus GlideAggregate cost, caps dataset size vs. BI columnar engines.
- **Where it's just "nobody built it yet":** rich interaction libraries (cross-filter, brush-link, drill), a reusable ACL-safe aggregate data resource, a bespoke-chart-spec generator, digital-signage rotation. **Verdict: realistic ceiling ≈ 80–90% of typical Power BI/Tableau *dashboard* richness for ServiceNow-sourced data; materially lower for cross-source ad-hoc analytics.**

### PART C — The Now Assist / native AI ceiling

**C9. Precise current limits (Verified-Documentation / Verified-Practitioner)**
- **Data Visualization Generation:** supported types = **single score, line, vertical bar, pie chart, list** — a subset even of the OOB palette. Prompt grammar is a rigid "data sentence" (aggregate → state → source → condition → grouping → trend → presentation). Requires `now.assist.creator` (+ `.analytics`, `now_assist_panel_user`) roles and tables registered in Semantic Table config (`sn_query_gen_table_config`). Practitioner failure mode: generic "problem on my side" errors tied to config/semantic-table registration. **The 5-type list is unchanged Zurich→Australia** (no release note shows expansion; confirmed via ServiceNow-authored Community prompting guide + Store listings + the ServiceNow/ServiceNowDocs GitHub mirror).
- **AI Data Explorer (AIDE):** NL questions → documented insights + visualizations, follow-up suggestions, "Standard" vs "Extended" (pattern-discovery) analysis, summarization, recommend-actions, collaboration. This is the 2026 flagship, delivered through Otto. Insight quality is real but it does not expose bespoke chart-grammar control. *(Verified-Documentation: ServiceNow Store, Community)*
- **Query Generation:** separate skill; requires **semantic table registration**; cross-table querying constrained (Database Views path; ~10k-row default). Australia adds a Query Generation component with its own "supported chart types" reference page. *(Verified-Documentation)*
- **Australia additions:** "Now Assist in Platform Analytics applications were enhanced and updated in the Australia release"; the headline analytics advances are **AIDE + Query Generation**, plus embedding dashboards in workspaces and Performance Analytics intraday tracking — **not** an expansion of the DV-Generation chart list. *(Verified-Documentation)*

**C10. Is AI analytics being "pushed systemwide"? — CONFIRMED, strongly (Verified-Documentation / Verified-Practitioner)**
- **Now Assist bundled into every tier.** Per a ServiceNow Community guide (td-p/3565858) and Elite partner Crossfuze, **on April 9, 2026, ServiceNow replaced its five legacy tiers (Standard, Pro, Pro Plus, Enterprise, Enterprise Plus) with three AI-native tiers (Foundation, Advanced, Prime); Now Assist, the Moveworks layer, Workflow Data Fabric, Context Engine, and AI Control Tower are bundled into every tier rather than sold as add-ons; legacy SKUs reach end of sale July 1, 2026.** *(Verified-Practitioner)*
- **Caveat on "bundled = free":** licensing advisory Redress Compliance notes overage "still bills per unit past the pool" and advises scoping "Prime to the agent population, not the whole seat count… Prime was needed by a build-and-run team measured in tens, not thousands." Bundling arrives at renewal; ServiceNow publishes no public Now Assist list prices. *(Verified-Practitioner, source-quality flagged)*
- **Otto (Knowledge 2026, May 5 2026):** a unified AI experience combining Now Assist + Moveworks + AI Experience across every department/system, delivered in the Australia release; "AI Data Explorer" is one of its four channels; "will be rolled out across all products in the year ahead." *(Verified-Documentation: ServiceNow Newsroom)*
- **Autonomous Data Analytics (Knowledge 2026):** Pyramid-fueled; "any person or AI agent can query the entire enterprise data estate in plain language." Marketing language explicitly targets every employee ("Give everyone the power to explore"). *(Verified-Documentation: investor.servicenow.com)*
- **Verdict: the user's belief is correct.** ServiceNow is making AI-driven analytics a default, systemwide, marketed-to-every-employee capability. This RAISES the bar — "we generate charts from NL" is now table stakes ServiceNow ships in-tier.

**C11. Can Now Assist AI do the four hard things? (Verified-Documentation / Inference)**
- **(a) Bespoke visualization matched to statistical shape/cardinality:** **Documented as NOT existing.** It picks from a fixed 5-type list via keyword ("as a pie chart"); no evidence of cardinality/distribution-driven spec generation.
- **(b) Autonomous KPI/metric discovery without a human specifying the metric:** **Not documented as existing.** DV Generation and Analytics Generation require the user to state the metric; AIDE suggests follow-ups within user-initiated exploration. Pyramid's semantic layer defines *canonical* (human-curated) metrics, not autonomous discovery. *(Inference)*
- **(c) Provable, persona-specific ACL-correctness of aggregate output:** **Documented as NOT existing / out of scope** — aggregate queries bypass ACLs and there is no proof mechanism. *(Verified-Documentation of the gap)*
- **(d) Continuous drift-detection and re-proposal as data/catalog changes:** **Not documented.** Performance Analytics adds intraday score tracking, and anomaly/threshold alerting exists, but autonomous "the catalog changed, here's a new recommended dashboard" is not documented. *(Inference)*

**C12. Has ANYONE shipped true adaptive chart-grammar generation? (Verified-Documentation / Inference)**
- **No major BI vendor has shipped "AI writes a bespoke chart spec fitted to the real statistical shape of the data" as a documented feature.** What's shipped is **template/encoding selection from a fixed library:**
  - **Tableau Pulse:** deterministic statistical engine computes facts; LLM writes NL insight *summaries*; visuals are standard metric line/breakdown charts — not adaptive grammar. *(Verified-Documentation: tableau.com/help)*
  - **Power BI Copilot:** "Copilot chooses the visual and its formatting, which the user can't control" — it *selects* a Power BI visual (card/line/table); nondeterministic; not spec-synthesis. Power Apps "Visualize with Copilot" aggregates a view into a chart with editable type. *(Verified-Documentation: Microsoft Learn)*
  - **ThoughtSpot Spotter / SpotterViz:** NL→insights + auto-dashboards from **"25+ native, out-of-the-box chart options,"** with Spotter "automatically selecting the best-fit chart" and custom charts via its Grammar-of-Graphics library **Muze** — still library selection + code extension, not generative grammar. *(Verified-Documentation: thoughtspot.com)*
  - **Sigma, Looker Gemini, Holistics AI, Zenlytic:** semantic-layer-grounded NL query + chart selection; explanations; multi-turn — no adaptive spec generation.
- **The adaptive-grammar idea lives in research, not products:** Data2Vis, VizML, Draco, Voyager/CompassQL, and Microsoft's **Flint** (a semantics-driven intermediate language compiling to Vega-Lite/ECharts/Chart.js, 2026 arXiv) — Flint explicitly separates "what to visualize" (LLM) from "how to visualize it well" (deterministic compiler). None is a shipped enterprise dashboard feature. *(Verified-Documentation: arXiv)*
- **Verdict: "AI generates a bespoke chart specification matched to the statistical shape of the data" is genuinely novel/uncontested as a *shipped product feature*** — but the underlying research is public and Microsoft is actively working it, so first-mover advantage is time-boxed. It is the strongest single technical differentiator in the thesis, but must be paired with correctness + native quality to be defensible, because "chart from NL" alone is now commoditized.

### D14. Decision-ready verdicts
- **(a) Technically buildable at high quality? YES.** The rendering ceiling is high; VividCharts proves it commercially. The real engineering is in interaction plumbing and ACL-safe data binding, not chart aesthetics. *(High confidence.)*
- **(b) Meaningfully differentiated from existing ServiceNow dashboard tools? YES — but on a narrow, defensible axis.** Beautiful native viz alone is NOT differentiated (VividCharts owns it). The differentiation is the **combination** VividCharts lacks: AI-driven insight/metric selection + **provable ACL-correctness**. That combination is white space today. *(Medium-high confidence; risk = ServiceNow closing it.)*
- **(c) Meaningfully differentiated from Now Assist's native AI? YES today.** Now Assist does 5-type template selection, no adaptive grammar, no autonomous KPI discovery, no ACL proofs, no drift-detection. A product doing **data-shape-adaptive chart-spec generation + provable correctness + native delivery** sits clearly beyond documented Now Assist capability. **But the moat is time-boxed:** ServiceNow's systemwide AI push (Otto, bundled Now Assist, Pyramid/Autonomous Data Analytics) means "AI from NL" is commoditizing fast. Build on the parts ServiceNow structurally under-serves — bespoke visual quality and correctness — not on NL-to-chart. *(Medium-high confidence.)*

## Recommendations

**Stage 1 — Native visualization core (0–3 months).**
- Build custom **Next Experience (UXF) components** with **ECharts** (permissive license, richest chart set, plain-JS safe) as the primary engine; keep Service Portal widget parity only for legacy portals. Avoid Highcharts unless a specific feature justifies the OEM license cost for Store redistribution. Avoid React-in-UXF for charts (Webpack sub-exports fragility). Use Figma/LLM/design-system tooling freely in the build; deliver via `snc ui-component`. Benchmark against VividCharts visual quality as the bar to clear.

**Stage 2 — Correctness moat (2–5 months, parallel).**
- Ship a **provably ACL-safe aggregate data resource**: inject the persona's effective ACL/domain query into GlideAggregate and validate equivalence against a GlideRecordSecure row-set on sample data; surface a per-tile "ACL-verified" badge. Make persona-specific correctness a demoable, auditable feature — it attacks the documented gap that neither VividCharts nor Now Assist addresses.

**Stage 3 — AI differentiator ServiceNow can't easily copy (4–9 months).**
- Do NOT compete on "NL → one of 5 charts" (Now Assist ships that free-in-tier). Ship **data-shape-adaptive chart-spec generation**: profile each field's cardinality/distribution/temporality, then generate a bespoke spec (Vega-Lite/ECharts option) via an LLM-plus-deterministic-compiler approach (Flint-style: LLM picks *what*, rules enforce *how*). Add **autonomous KPI discovery** from catalog/process metadata and **drift-detection re-proposal** — all four are documented as absent from Now Assist.

**Benchmarks / thresholds that would change the plan:**
- A ServiceNow release note showing DV Generation expanding beyond 5 chart types OR adding data-shape adaptivity → the viz-AI wedge weakens; shift weight to correctness + cross-source.
- Pyramid/Autonomous Data Analytics shipping an ACL-provable aggregate layer → the correctness moat erodes; accelerate the adaptive-grammar differentiator.
- A Store ISV appearing that combines (a)+(b)+(c) → white space contested; compete on depth of correctness proofs and export/signage polish.
- If Highcharts is on the table, get the OEM quote *before* committing — it can dominate Store-app unit economics.

## Caveats — what could not be verified & biggest risks
- **VividCharts' internal ACL handling is unverified.** Whether its chart-type scripts use GlideRecordSecure or manually replicate ACL filters on aggregates is inferred from its documented GlideRecord/GlideAggregate architecture, not confirmed.
