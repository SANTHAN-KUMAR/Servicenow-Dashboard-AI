| # | Gap | Confidence | Citation | Why it matters |

| 2.1 | **Native real-time push exists via the "Record Watcher" Data Resource** (AMB-backed), introduced in the **Tokyo** release — a documented, supported mechanism for live-updating UI Builder pages without polling. | Confirmed | [How to use AMB Record Watcher in ServiceNow UIB](https://www.servicenow.com/community/next-experience-articles/how-to-use-amb-record-watcher-in-servicenow-uib/ta-p/2352975) | This is the correct mechanism for "live dashboard" refresh in Layer 4 — build on this, not on raw AMB (see 2.2). |
| 2.2 | **Raw/direct AMB usage inside hand-coded pro-code components is explicitly unsupported** — ServiceNow itself told a developer building this pattern "its usage was not supported and there were no docs that could be passed on." ## 4. What this registry changes in the architecture (cross-references only — see `02-...` for full detail)

- **Governance (§1):** promotion strategy must lead with Source Control, not Update Sets (1.1, 1.5, 1.6); ATF cannot be the primary test strategy (1.8–1.9); **ServiceNow will not support the custom components themselves, full stop (1.10)** — this is the single fact most worth repeating verbatim to any client evaluating this approach.
- **Runtime (§2):** live-refresh design must use the Record Watcher Data Resource, not raw AMB, with an explicit ~200-record throttling awareness (2.1–2.2); i18n/RTL are real, unbudgeted engineering workstreams if multi-language support is required (2.7–2.9); Shadow-DOM chart-rendering performance at scale is a genuinely untested risk requiring its own load test, not an assumption that generic ECharts benchmarks transfer unchanged (2.11).
- **Licensing (§3):** ACL enforcement is not just a differentiator — it's a **named Store-certification rejection criterion** (3.2), which strengthens the case for building Layer 1 regardless of go-to-market path; ECharts requires LICENSE/NOTICE retention and a trademark-naming carve-out (3.4); watch the custom-table/App-Engine-entitlement question if this product's own metadata needs new tables (3.5–3.6).
- **Everything in §1–3 that is marked Unverified or Not Found is an explicit follow-up list**, not a gap to quietly assume away: KB1952650 full text (1.2), the named-export community thread (1.13), `glide.db.max_view_records` / export-limit KB full text (2.4–2.5), the Store Publisher Portal's bundled-JS certification checklist (3.2), a live G2 re-check (3.3), and the Custom Table Guide PDF (3.6).
